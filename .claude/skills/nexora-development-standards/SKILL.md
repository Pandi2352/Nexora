# Nexora OS — Development Standards

Apply these rules to every current and future module in Nexora OS. Architecture details: `docs/FRONTEND_ARCHITECTURE.md`, `docs/BACKEND_ARCHITECTURE.md`.

## 1. Modular file and folder structure

- **File size:** keep every file under ~150–200 lines. Split before it grows past that.
- **Frontend (layer-based):**
  - Subcomponents go in `client/src/components/<module>/`.
  - Page files go in `client/src/pages/<module>/<Page>.tsx`. A page only coordinates state, layout and data fetching; it renders subcomponents and holds no large JSX blocks.
  - API calls go in `client/src/services/<module>.service.ts`; never call Axios from pages or components.
  - Types go in `client/src/types/`; shared hooks go in `client/src/hooks/`.
  - Providers go in `client/src/context/<name>/` as `<name>-context.ts` + `<Name>Provider.tsx`.
  - Sidebar menus, paths and quick actions are data in `client/src/config/` (`navigation.ts`, `paths.ts`, `quickActions.ts`). Never hard-code routes in components; use `paths.ts`.
  - Routes live in `client/src/routes/` (`router.tsx`, `lazyPage.tsx`, `guards/`); layouts live in `client/src/layouts/`.
  - Shared primitives live in `components/ui/`; shared composites (PageHeader, EmptyState, …) live in `components/common/`. Never duplicate them inside a module.
  - Use `cn()` from `@/lib/cn` to merge class names.
- **Backend:** each module in `server/src/modules/<module>/` has separate files:
  - `<module>.module.ts`
  - `<module>.controller.ts`
  - `<module>.service.ts`
  - `<module>.repository.ts` (when it centralizes tenant-scoped queries)
  - `schemas/<module>.schema.ts`
  - `dto/create-<module>.dto.ts`, `dto/update-<module>.dto.ts`, `dto/list-<module>-query.dto.ts`
  - `policies/<module>.policy.ts` (when resource-level rules exist)
  - `<module>.service.spec.ts`

## 1a. Layout, routing and Outlet (frontend)

**One component per file.** A component with its own state, behaviour or variant gets its own file. Tiny presentational siblings (e.g. `DropdownLabel` + `DropdownSeparator`) may share one.

**Config is the single source of truth**
- `config/paths.ts`: `workspaceSegments` (paths under `/workspace/:workspaceSlug`) and `paths` builders (`paths.workspace(slug, segment)`). No URL string literals anywhere else.
- `config/navigation.ts`: sidebar sections → items → children, each pointing to a `workspaceSegments` value. Breadcrumbs and placeholder titles are derived from it (`lib/navigation.ts` → `findNavTrail`); never duplicate labels.
- `config/quickActions.ts`: navbar quick-create items.
- To add a sidebar menu, add the segment to `paths.ts`, then the item to `navigation.ts`. The route is generated.

**Routes (`client/src/routes/`)**
| File | Holds |
|---|---|
| `router.tsx` | `createBrowserRouter` (module-level, not exported) + `AppRouter` component |
| `publicRoutes.tsx` | Auth and workspace-selection routes under `AuthLayout` |
| `workspaceRoutes.tsx` | `/workspace/:workspaceSlug` under `AppLayout` |
| `pages.ts` | Every routed page, wrapped with `lazyPage(() => import(...))` |
| `lazyPage.tsx` | `React.lazy` + `Suspense` with `PageSkeleton` fallback |
| `guards/` | `RequireAuth`, `RequireWorkspace`, `RequirePlatform` (when auth exists) |

**Outlet rules**
- Layouts (`layouts/AppLayout.tsx`, `AuthLayout.tsx`) render the shell and exactly one `<Outlet />` inside `<main id="main-content">`.
- **The outlet area uses the full width.** No `max-w-*` / `mx-auto` centring on the outlet wrapper or on pages, so there is no empty space left and right on wide screens. Keep only the page gutter (`px-4 sm:px-6 py-6`). Constrain width only inside a component that needs it for readability (e.g. a long-form text block or a narrow form), never the whole page.
- Pages are lazy and the Suspense boundary lives in `lazyPage` (inside the Outlet), so the sidebar and navbar never unmount or flash while a page chunk loads.
- Each layout route has a **pathless child route with `errorElement: <RouteErrorPage />`** wrapping the pages, so page errors render inside the Outlet and the shell stays. Every top-level route also has an `errorElement`.
- Index route redirects with `<Navigate to=... replace />`; a `path: '*'` child renders `NotFound` inside the layout.
- The scroll container (`main`) resets to top on navigation (`useScrollTopOnNavigate`); `SkipLink` targets `#main-content`.
- Pages set the tab title with `useDocumentTitle`. Workspace context comes from `useWorkspaceSlug()`, never by parsing the URL.

**Layout components (ported from the svksPrint-iq design; keep this look)**
- `components/layout/sidebar/`:
  - `Sidebar`: desktop column that collapses to an icon rail (`lg:w-(--sidebar-width)` / `lg:w-(--sidebar-width-collapsed)`, width transition). Below `lg` it is a drawer with a fading backdrop; `inert` when hidden.
  - `SidebarBrand`: `LogoMark` (`components/common/Logo.tsx`) + "Nexora **OS**" (`text-sm font-bold`, "OS" in `brand-600`) + workspace name (`text-xs text-slate-500`). It links to the dashboard.
  - `SidebarNav` (`custom-scrollbar px-3 py-4`) → `SidebarSection` → `SidebarLink` / `SidebarGroup`.
  - `SidebarFlyout`: in icon-rail mode, a fixed-position label/submenu on hover or focus, kept inside the viewport, so the scrolling nav never clips it.
  - `SidebarFooter`: account link only (Avatar, name, role) to `/account`. The collapse toggle is **not** in the sidebar.
  - `SidebarIcon` (`active` prop) and `sidebarStyles.ts` (`SIDEBAR_ID`, `navRowClass`, `childRowClass`).
- `components/layout/navbar/`:
  - `Navbar`: `h-16 px-3.5 sm:px-5`. **`SidebarToggle` on the left (first item)**, then right-aligned `SearchTrigger`, `QuickCreateMenu`, `NotificationsMenu`, a divider and `UserMenu`. **No breadcrumbs in the navbar**; page context comes from the page title (`PageHeader`).
  - `SidebarToggle`: calls `toggle()`. On desktop it collapses or expands the icon rail (PanelLeftClose/PanelLeftOpen); on mobile it opens the drawer (Menu icon). Its tooltip includes `(Ctrl+B)`.
  - `SearchTrigger`: "Search pages and actions…" + `Ctrl K`, `w-64 xl:w-80`.
  - `QuickCreateMenu`: a solid `brand-600` "+ New" button; items have a label and description.
  - `NotificationsMenu`: header with "Mark all as read", list, "View all notifications" footer.
  - `UserMenu`: avatar, name and role chip. The menu holds account, notifications and workspace settings, **Switch workspace** (workspace list with a check on the current one, plus All workspaces), and Sign out.
- **Sidebar styling comes only from `sidebarStyles.ts`.** Never write row classes inline.
  - `navRowClass(active, collapsed)`: `text-sm font-medium`, `px-3 py-2` (`h-10` centred when collapsed), `gap-3`. Idle `text-slate-600 hover:bg-slate-100`; active `bg-brand-50 text-brand-700`; focus `ring-2 ring-brand-500`.
  - `childRowClass(active)`: `px-3 py-1.5 text-sm`. Idle `text-slate-500`; active `font-medium text-brand-700` (no background).
  - `SidebarIcon`: `size-5`, `text-slate-400 group-hover:text-slate-600`, active `text-brand-600`.
  - Group: chevron `size-4 text-slate-400` rotates when open. Submenu opens with a `grid-rows-[0fr→1fr]` transition. Child list `ml-5 border-l border-slate-200 pl-3`. The parent is highlighted only while closed with an active child.
  - Section: `mt-5` between sections; label `mb-1.5 px-3 text-[11px] font-semibold uppercase tracking-wider text-slate-400` (design choice). In the icon rail, sections are separated by `border-t border-slate-100`.
- Dropdown panels: `rounded-md border border-slate-200 bg-white`, no padding by default (pass `menuClassName="w-72 py-1.5"`). `DropdownItem` takes `label`, `description`, `icon`, `to`, `hint`, `disabled` and `trailing`, with full-bleed rows `px-3 py-2 hover:bg-slate-50`. Menus close on outside click, Escape, item select and route change.
- Sidebar state lives in `context/sidebar/` (`isCollapsed`, `isDesktop`, `isMobileOpen`, `toggle`, …):
  - `useMediaQuery(DESKTOP_QUERY)`, and the collapsed preference persists via `useLocalStorage('nexora.sidebar.collapsed')`.
  - The drawer closes on navigation or when the viewport grows to desktop.
  - Escape closes the drawer and body scroll is locked while it is open.
  - `useHotkey('b')` toggles the sidebar.
- Tests: `src/test/setup.ts` stubs `window.matchMedia` (desktop) for jsdom.
- **Verify visual changes on screen**, not just with tests. Run the dev server and take a headless Edge screenshot with `npx playwright screenshot --channel msedge --viewport-size 1280,900 <url> out.png`. Add `--load-storage state.json` to preset `localStorage` (e.g. the collapsed sidebar).

**Error handling (one system, reused everywhere)**
| File | Role |
|---|---|
| `config/errorCodes.ts` | All error definitions: status, title, description, icon, actions. Add or reword errors only here. |
| `types/error.ts` | `ErrorKey`, `ErrorAction`, `ErrorDefinition`, `ResolvedError` |
| `lib/errors.ts` | `resolveError(unknown)` (route responses, `Response`, `AppError`, backend `{ statusCode, requestId }`, network, stale chunk), `fromStatus`, `getErrorDefinition` |
| `lib/app-error.ts` | `AppError(status, message?, requestId?)`: throw it to show a specific error screen |
| `components/common/ErrorState.tsx` + `ErrorActions.tsx` | Reusable error UI; actions come from the definition |
| `pages/errors/RouteErrorPage.tsx` | `errorElement`: `resolveError(useRouteError())` → `ErrorState` |
| `pages/errors/ErrorPage.tsx` | `/error/:status` or `<ErrorPage status={403} />` |

- Never write error titles or messages inline. Use `ErrorState` with `resolveError(err)` or `fromStatus(code)`.
- To block a page: `throw new AppError(403)`. The nearest `errorElement` renders it inside the layout.
- For a failed data load inside a page: `<ErrorState error={resolveError(err)} onRetry={refetch} />`.
- Show the API `requestId` when present. Raw messages appear in development only.

**Fast-refresh safe exports:** `.tsx` files export components only. Constants, helpers and contexts go in `.ts` files (`sidebarStyles.ts`, `sidebar-context.ts`, `button-variants.ts`).

## 2. Shared UI components everywhere

Always import from `@/components/ui`. Never build one-off buttons, inputs or modals inside a feature.

| Component | Notes |
|---|---|
| `Button` | `variant`: `primary`, `secondary`, `outline`, `ghost`, `danger`, `success` · `size`: `sm`, `md`, `lg` · supports `loading`, `disabled` |
| `IconButton` | Requires an `aria-label` |
| `Card` | `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, `CardFooter` |
| `Modal` | Backdrop, focus trap, Esc to close, action footer |
| `Drawer` | Slide-over for detail panels and comparisons |
| `Input` | Label, icon, error, hint; error linked via `aria-describedby` |
| `Select` | Labelled select with options |
| `StatusBadge` | `critical`, `warning`, `info`, `success`, `neutral`; always shows text, not colour alone |
| `Badge`, `Dropdown`, `Avatar`, `Kbd` | — |
| `DataTable`, `Pagination`, `EmptyState`, `ErrorState`, `Skeleton`, `PermissionDenied` | Required states for data screens |

If a needed primitive does not exist, add it to `components/ui/` first, then use it.

Also reuse: `TagInput` (ui), `FormSection` (common, bordered card for full-page forms), `useWorkspaceMembers()` (member select options + id → name map). **Create/edit forms are full pages with their own routes** (e.g. `/support/tickets/new`, `/:id/edit`), not modals; keep form state, validation and payload mapping in a `<module>-form.ts` model file and a `use<Module>Form` hook. Reference implementation: the Support module (`pages/support`, `components/support`, `server/src/modules/support`).

## 3. Strict UI design rules

- **`rounded-md` everywhere:** cards, inputs, buttons, badges, modals, drawers, dropdowns, tables.
  - Never use `rounded`, `rounded-sm`, `rounded-lg`, `rounded-xl`, `rounded-2xl` or `rounded-3xl`.
  - Exceptions: `rounded-full` for avatars and dot indicators only.
- **No drop shadows:**
  - Never use `shadow-*` utilities (`shadow-xs`, `shadow-sm`, `shadow`, `shadow-md`, `shadow-lg`, …) or custom `box-shadow`.
  - Separate surfaces with flat borders (`border border-slate-200`, dark: `border-slate-800`) and subtle background contrast (`bg-slate-50`).
  - Focus is shown with a `ring`/outline, not a shadow.
- **`client/src/index.css` is owned by the user and is the source of truth for the theme.** Never rewrite or reorder it; read tokens from it before styling, and only add to it when asked.
  - `brand-50…900`: brand identity (logo tile, active sidebar row, avatars, highlights).
  - `primary-50…900`: buttons, badges and focus rings (`bg-primary-600`, `outline-primary-600`).
  - Text on colour uses `-600` or darker (white on `-600` = 5.36:1; white on `-500` fails).
  - Layout sizes come from tokens: sidebar `w-(--sidebar-width)`, collapsed `w-(--sidebar-width-collapsed)`.
  - Body background, text colour and font are set globally in `@layer base`; don't repeat `bg-slate-50`/`text-slate-800` on layouts.
  - Scrollbars are styled globally. Use `custom-scrollbar` on the page outlet and panels, and `scrollbar-thin` on narrow lists such as the sidebar nav.
  - No hard-coded hex values in components. No hard-coded hex values in components.
- Every interactive element has a visible focus style and a pointer cursor. Follow the **nexora-interaction-states** skill.

## 4. Backend conventions

### UUIDs and Database Schemas (`server/src/database/base.schema.ts`)

- All entity IDs and references are UUID v4 strings, generated with `IdUtil.generateUuid()` and validated with `IdUtil.isValidUuid()` / `@IsUUID('4')`.
- Never use MongoDB `ObjectId`, `Types.ObjectId` or `isValidObjectId`.
- Schemas extend the base classes in `server/src/database/base.schema.ts`:
  - `BaseDocument`: UUID `_id`, audit actors (`createdBy`, `updatedBy`), and audit timestamps (`createdAt`, `updatedAt`).
  - `SoftDeleteDocument`: extends `BaseDocument` with `isDeleted` (boolean, indexed), `deletedAt`, and `deletedBy`.
  - `TenantDocument`: extends `BaseDocument` with required, indexed `organizationId`. Use for all tenant-owned entities.
  - `TenantSoftDeleteDocument`: combines tenant scoping and soft-delete capabilities.
- Standard options: use `defaultSchemaOptions` or `createBaseSchema(ModelClass)` (`applyBaseSchemaPlugins(schema)`), which automatically enables `timestamps: true`, `versionKey: false`, maps `id = _id`, and removes `__v` in `toJSON` and `toObject`.
- IDs are generated with Node's `crypto.randomUUID()` via `IdUtil`. Don't add the `uuid` package.

```ts
@Schema({ collection: 'tasks', ...defaultSchemaOptions })
export class Task extends TenantSoftDeleteDocument {
  @Prop({ type: String, required: true, trim: true, maxlength: 200 })
  title: string;

  @Prop({ type: String })
  assigneeId?: string; // UUID of a user
}
export const TaskSchema = createBaseSchema(Task);
TaskSchema.index({ organizationId: 1, isDeleted: 1, createdAt: -1 });
```

### Tenant scoping

- Every tenant-owned schema has `organizationId: string`.
- Every query, update, delete, aggregation (`$match` first) and background job filters by `organizationId`.
- `organizationId` comes from the resolved tenant context, never from the request body.
- A record in another tenant returns 404.

### Unified API Responses & Centralized HTTP Logging

Every API endpoint strictly conforms to the uniform response envelope.

**Success Response Envelope (`ApiResponse<T>`):**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Tasks fetched",
  "data": [],
  "meta": { "total": 0, "page": 1, "limit": 20, "totalPages": 0, "hasNextPage": false, "hasPrevPage": false },
  "requestId": "c7a38914-1fbc-499b-b9f1-c8b598b0f4a2",
  "timestamp": "2026-10-19T10:30:00.000Z"
}
```

**Error Response Envelope (`ApiErrorResponse`):**
```json
{
  "success": false,
  "statusCode": 404,
  "code": "NOT_FOUND",
  "message": "Task not found",
  "details": [{ "field": "taskId", "message": "Task does not exist in workspace" }],
  "requestId": "c7a38914-1fbc-499b-b9f1-c8b598b0f4a2",
  "timestamp": "2026-10-19T10:30:00.000Z"
}
```

- Enforced globally by `ApiResponseInterceptor` and `AllExceptionsFilter`. Controllers use `createApiResponse(...)` or return data.
- Never manually build raw error envelopes in controllers. Throw `AppException` and let the global filter format it.
- **HTTP Request & Response Logger:** `HttpLoggingInterceptor` automatically logs `[HTTP] [METHOD] /path STATUS +DURATIONms [req:ID] [ip:IP] [usr:USER_ID]`. It handles performance timing, correlates request IDs, and sanitizes sensitive credentials/payloads.

### Common helpers (`@/common`)

| Helper | Use |
|---|---|
| `createApiResponse(data, message?, meta?)` | Every successful controller response |
| `ApiResponse<T>`, `ApiErrorResponse` | Standard API response interfaces |
| `ApiResponseInterceptor`, `HttpLoggingInterceptor` | Global interceptors wired in `main.ts` |
| `BaseDocument`, `SoftDeleteDocument`, `TenantDocument`, `TenantSoftDeleteDocument` | Base classes for every Mongoose collection |
| `defaultSchemaOptions`, `createBaseSchema` | Schema options and plugins (UUID `id` virtual, no `__v`) |
| `PaginationDto` | Base query DTO (`page`, `limit` ≤ 100, `sort`, `order`, `search`, `skip` getter); list DTOs extend it and restrict `sort` with `@IsIn` |
| `createPaginationMeta(total, page, limit)` | `meta` for paginated lists |
| `AppException(status, message, code?, details?)` | The only way services signal errors |
| `ErrorCode` | Stable error codes (match the client's `config/errorCodes.ts`) |
| `IdUtil` | `generateUuid()`, `isValidUuid()` |
| `StringUtil` | `normalizeEmail`, `slugify`, `escapeRegex` (before any `$regex`), `toCsvSafe` (exports) |
| `DateUtil` | `toIsoString`, `addMinutes`, `addDays`, `isExpired` (UTC) |
| `HashUtil` | `sha256`, `randomToken`, `safeEqualHex`, `hashPassword`, `verifyPassword` |
| `setupSwagger(app)`, `createValidationPipe()`, `AllExceptionsFilter`, `requestIdMiddleware` | Wired once in `main.ts`; don't re-register in modules |

**Imports:** outside `server/src/common/`, import from `'@/common'` (the Nest CLI rewrites the alias at build). Inside `common/`, use relative imports.

**Configuration:** every env variable is declared and validated in `server/src/config/env.validation.ts`, and the app refuses to start if one is invalid. Read values with `ConfigService<EnvironmentVariables, true>` → `config.get('KEY', { infer: true })`. Never read `process.env` in feature code, and never give a secret a default value. A new variable goes in the class, in `.env.example` and in the config table in `docs/BACKEND_ARCHITECTURE.md` § 17.

**Health:** `GET /api/v1/health/live` (process) and `/health/ready` (MongoDB connected, otherwise 503).

**Server toolchain:** Node 20.19 (installed), NestJS 12 runtime, Nest CLI 11.0.24 + schematics 11.1.0 (v12 needs Node 22). The server uses **TypeScript 6.0.3**, a documented exception (`docs/TECH_STACK.md` § 10a), because TS 7.0 lacks the compiler API the Nest CLI needs. Re-check with `npm view typescript version` and upgrade once TS 7.1 restores the API. The client stays on the latest TS.

## 5. Packages and libraries: latest stable versions only

- **Before every install, check the latest version:** `npm view <pkg> version`. Never take a version number from memory, training data or a scaffold template, because it is likely outdated.
- Install with an explicit `@latest`: `npm install <pkg>@latest` (or `-D` for dev dependencies).
- Scaffolders (create-vite, nest new, …) write stale version ranges. After scaffolding, reinstall **every** package with `@latest`.
- After installing, confirm that `package.json` records the latest version (e.g. `"vite": "^8.3.4"`, not `^8.3.0`) and that `npm ls --depth=0` matches `npm view <pkg> version`.
- **Remove unused packages.** Install a package only when code uses it, and uninstall anything nothing references (`npm uninstall <pkg>`). Don't pre-install for future milestones.
- **Routing:** use `react-router-dom` only (never the bare `react-router` package). Import from `react-router-dom`.
- Read the package's **current** documentation before writing code against it. Don't use APIs from older majors. For example:
  - Tailwind v4 is configured CSS-first with `@theme`; there is no `tailwind.config.js`.
  - React Router uses the current data-router APIs.
  - NestJS and Mongoose use their current major's APIs.
- No beta, rc, canary or `next` tags unless approved and recorded in `docs/TECH_STACK.md`.
- Never add deprecated or unmaintained packages. Check `npm view <pkg> deprecated`, the last publish date and open security advisories.
- Don't pin to an old major to avoid migration work. If the latest major breaks something, fix the code; if that's not possible, record the exception and reason in `docs/TECH_STACK.md`.
- Commit `package-lock.json`. Exact versions are reproducible through the lockfile.
- Run `npm outdated` and `npm audit` before each milestone and upgrade to the latest stable versions.
- **Node.js: use the installed version (20.19.4). Never install, require or suggest a Node upgrade, and never run tools through `npx -p node@<other>`.** "Latest" means **the newest version whose `engines.node` supports the installed Node**. Check with `node scripts/check-latest.mjs <pkg> [pkg...]`, then build and run, because a dependency can still need a newer Node. Each pinned-below-latest package goes in `docs/TECH_STACK.md` § 10a.
- Match `@types/node` to the installed Node major (`@types/node@20`).
- Use the installed npm (10.8.2). If it hits its known peer-dependency bug on a fresh install, use `npx npm@11` (supports Node 20), not npm 12.
- Every new dependency gets a one-line purpose in `docs/TECH_STACK.md`.

### Tailwind CSS v4 setup (Vite plugin — official steps)

1. Check versions: `npm view tailwindcss version` and `npm view @tailwindcss/vite version`.
2. Install: `npm install -D tailwindcss@latest @tailwindcss/vite@latest`.
3. Add the plugin in `vite.config.ts`:
   ```ts
   import tailwindcss from '@tailwindcss/vite'
   export default defineConfig({ plugins: [react(), tailwindcss()] })
   ```
4. In `src/index.css`: `@import 'tailwindcss';` and put design tokens in `@theme { }`.
5. Import `index.css` once in `main.tsx`.
6. Do not create `tailwind.config.js` or `postcss.config.js`, and do not install `postcss` or `autoprefixer`.

## 6. Review checklist

- [ ] No file over ~200 lines
- [ ] Page is a coordinator; subcomponents live in `components/<module>/`
- [ ] One component per file; `.tsx` files export only components
- [ ] New pages registered in `routes/pages.ts` via `lazyPage`; menus added via `paths.ts` + `navigation.ts`
- [ ] Layout keeps a single `<Outlet />`; page errors handled by a pathless `errorElement` route
- [ ] API calls go through `services/`; routes come from `config/paths.ts`
- [ ] Only `@/components/ui` primitives used
- [ ] Only `rounded-md` (or `rounded-full` for avatars)
- [ ] No `shadow-*` classes and no `box-shadow`
- [ ] UUID v4 IDs; no `ObjectId` anywhere
- [ ] `organizationId` scoping on schema, queries and jobs
- [ ] Responses via `createApiResponse`; lists via `PaginationDto` + `createPaginationMeta`
- [ ] DTOs validate every input; IDs use `@IsUUID('4')`
- [ ] Latest version checked with `npm view` before install; `package.json` shows that exact latest version
- [ ] No unused packages in `package.json`
- [ ] Routing uses `react-router-dom`
- [ ] No breadcrumbs in the navbar; the sidebar toggle is the first (left) navbar item
