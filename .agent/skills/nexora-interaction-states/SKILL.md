# Nexora OS — Cursor and Interaction States

Tailwind v4 resets `<button>` to `cursor: default`. Nexora restores the pointer globally, and every interactive element must still have its full set of states.

## 1. Global cursor base (in `client/src/index.css`, user-owned)

`client/src/index.css` `@layer base` sets `cursor: pointer` on enabled `button`, `[role=button]`, `[type=button|submit|reset]`, `summary`, `a`, `label[for]`, `select`, checkboxes and radios. Never remove or rewrite it; it is the user's file.

Not covered globally, so handle these in components:
- Disabled controls: add `disabled:cursor-not-allowed` (already in `Button` and `IconButton`).
- `[role=menuitem]`, `[role=tab]`, `[role=option]` on non-button elements: add `cursor-pointer`. Prefer rendering them as `<button>` or `<a>`.
- File inputs and drop zones: wrap in `<label htmlFor>` or add `cursor-pointer`.

## 2. When to add `cursor-pointer` yourself

The base layer covers native buttons, links, ARIA roles and form controls. Add `cursor-pointer` explicitly when a **non-button element is clickable**:

| Case | Do |
|---|---|
| Clickable table row / card / list item with `onClick` | Prefer wrapping its content in a `<Link>` or `<button>`. If not possible: `role="button"`, `tabIndex={0}`, Enter/Space handler, and `cursor-pointer` |
| Custom file drop zone | `<label htmlFor>` around it (pointer comes from `label[for]`) or `cursor-pointer` |
| Draggable item (Kanban card) | `cursor-grab active:cursor-grabbing` |
| Resizable handle | `cursor-col-resize` / `cursor-row-resize` |
| Text input, textarea | Leave the default text cursor |
| Read-only / static text, badges, avatars that do nothing | No pointer; a pointer promises an action |

Never put `onClick` on a bare `<div>` or `<span>` without `role`, `tabIndex` and keyboard handling.

## 3. Required states for every interactive element

| State | Rule |
|---|---|
| Hover | Visible change: `hover:bg-slate-100` (neutral), `hover:bg-primary-700` (primary), `hover:text-slate-900` (links) |
| Focus | `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-primary-600` (use `-outline-offset-2` inside tight containers like the sidebar). Never `outline-none` without a replacement. |
| Active / selected | Distinct from hover. Selected navigation: `bg-brand-50 text-brand-700` with a `brand-600` icon. Set `aria-current="page"` / `aria-selected` / `aria-pressed` as applicable. |
| Disabled | Native `disabled` (or `aria-disabled="true"` for links) + `disabled:opacity-50 disabled:cursor-not-allowed`. Don't use `pointer-events-none`, because it hides the not-allowed cursor. |
| Loading | Disable the control and show a spinner or label change; block double submits. |
| Transition | `transition-colors` only; no shadows, no scale effects. |

## 4. Primitives already follow this

Use `Button`, `IconButton`, `Dropdown`/`DropdownItem`, `SidebarLink` and `buttonVariants()` from `@/components/ui` and the layout components. They include hover, focus-visible, disabled and cursor states. Style links as buttons with `buttonVariants()`, never by copying classes.

## 5. Contrast

- Text on colour: white on `brand-600` / `primary-600` (5.36:1). Never put white text on `-500` or lighter (3.68:1 fails).
- Muted text: `slate-500` minimum on white. `slate-400` fails (2.56:1). Use it only for decorative icons and the uppercase sidebar/menu section labels, which are a design choice the user approved.

## 6. Review checklist

- [ ] Every clickable element shows a pointer; disabled ones show not-allowed
- [ ] No `onClick` on non-interactive elements without `role`, `tabIndex` and a keyboard handler
- [ ] Hover, focus-visible, active and disabled states present and distinct
- [ ] No `pointer-events-none` on disabled controls; no `outline-none` without a replacement
- [ ] Drag handles use `cursor-grab` / `active:cursor-grabbing`
